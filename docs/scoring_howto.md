# 面试答法：模型打分到底是怎么打的

> 这份文档解决一个具体问题：面试官问"你这个项目的模型打分是怎么打的"时，你怎么答得既准确又有工程判断。
> 全文白话，数字都是本项目实测出来的，末尾有一段可以直接背的 60 秒口播稿。

---

## 1. 一句话版本（10 秒版）

"评分分两层：**规则打分做确定性底线，模型打分做语义判断**，两者都落进同一条评分记录里，
用哪个口径写在 `method` 字段上；分数按题目的评分维度加权算出来，最后还会跑一次独立复核来验证这套口径稳不稳。"

---

## 2. 完整版（60~90 秒，按四层讲）

### 2.1 先说输入是什么（面试官最想确认你"打分不是拍脑袋"）

每道题出题时就带着自己的**评分维度**和**参考要点**，不是临场发挥：

- 维度：题库里每题 2 个维度，绝大多数是「覆盖度（权重 1.0）+ 深度与取舍（权重 0.6）」；
  另有 15 题是「结构（1.0）+ 量化与证据（0.6）」。
- 参考要点：每个维度下列出这道题真正要听到的关键点（例：GIL 那道题是
  覆盖度 = CPU密集 / IO密集 / 多进程 / 异步，深度与取舍 = 实测）。

所以"打分"是把**回答**和**这道题的参考要点**做对照，不是和某个绝对标准做对照。

### 2.2 怎么算分（把公式讲出来，比形容词可信）

- 每个维度先得 0~1 的分 → 按维度权重加权求和再归一化 → 得到这道题的总分（0~1）。
- 阈值：≥0.7 判"扎实"，0.4~0.7 判"一般"，<0.4 判"偏弱"。
- 偏弱**且**缺失要点 ≥2 个，才会触发追问（最多 2 层），追问也是按最低分维度问、只问没问过的要点。

### 2.3 谁在打分（这条是重点：为什么两层）

1. **模型分（主判）**：把题目、评分维度、参考要点、候选人回答一起给模型，要求它输出**结构化的评分记录**
   （各维度分、命中的要点、漏掉的要点、判定、一条改进建议），并且约束"命中和漏掉的要点只能从参考要点里原样挑，
   不许自己造词"。用 JSON 强约束 + 解析失败自动修复一轮；模型不稳定时按配置的模型链降级。
2. **规则分（兜底）**：纯确定性——统计回答里命中了几个参考要点，同样按权重加权。
   模型不可用、超时、输出不合规时全链路仍能跑完，只是把 `method` 标成规则口径。

**为什么要两层，而不是只用模型？** 因为这两个口径各有致命弱点，实测过：

| 同一道题、同一个意思的两种说法 | 规则分 | 模型分 |
| --- | --- | --- |
| 用词与参考要点一致（"CPU密集/多进程/异步…实测 QPS 提升 3 倍"） | **1.00** | 0.88 |
| 换成自己的话讲同样的内容（"全局解释器锁…计算密集型拆多进程…协程"） | **0.00** | 0.95 |

结论：**规则分对措辞极度敏感（换说法就从 1.00 掉到 0.00），模型分对措辞不敏感（0.88 ↔ 0.95）。**
如果只用规则分，会把"讲得很清楚但没用原词"的人判成 0 分；如果只用模型分，就没有可复现的底线、
模型一抖分数就漂。所以设计是"模型主判 + 规则兜底 + 两个口径都留痕"。

### 2.4 判完之后（让分数可被质疑，而不是只被相信）

- 每条评分都落盘：各维度分、命中要点、缺失要点、判定、打分方式（模型/规则）。
- 有**机器复核协议**：换一套不同协议（逐条判定要点是否真被答到）重评一遍，和自动分对齐，看两套口径一致不一致。
- 有**人评对照**：评分表由本人独立打分，算"一致率（差值 ≤0.2 视为一致）+ 平均绝对误差"。

## 3. 实测佐证（每个数字都能指着产物说）

| 指标 | 值 | 口径说明 |
| --- | --- | --- |
| 与人评一致性 | 一致率 1.00（7/7）、MAE **0.0371** | 7 道题，同一场；逐题偏差 −0.05~+0.05 |
| 偏差方向 | 机器分在两端更绝对 | 判"不合格"直接给 0（人评会给 0.05）；判"扎实"给 0.83~1.00（人评压到 0.80~0.95） |
| 机器复核一致性 | 一致率 1.00（7/7）、MAE **0.0157** | 只证明两套机器协议口径自洽，**不等于评分准确** |
| 跨模型差异 | 单题最大差 **18 个百分点**，综合差 14 个百分点 | 同一份输入换个模型（qwen-plus ↔ deepseek），互有高低、无系统性方向 |
| 要点命中口径 | 要点覆盖率 0.462 / 0.615（两场） | 命中要点数 / 全部参考要点数 |

## 4. 会被追问的 9 个点 + 安全答法

| 追问 | 怎么答 |
| --- | --- |
| 0~1 这个分数怎么来的，有依据吗？ | 维度分是"该维度参考要点的覆盖程度"，总分是按维度权重加权归一化；权重写在题库里（覆盖度 1.0、深度 0.6），不是临时拍的。 |
| 为什么用模型而不是纯规则？ | 实测：同一个意思换个说法，规则分从 1.00 掉到 0.00，模型分 0.88→0.95。纯规则会误杀"讲清楚但没用原词"的人。 |
| 模型打分会不会不稳定？ | 会，所以三件事：① 用 JSON 强约束 + 解析失败自动修复；② 温度固定 0.3；③ 有确定性规则分兜底，并把打分方式记进产物，事后能区分。 |
| 你怎么知道模型打得准？ | 两条对照：机器复核（换协议重评）+ 人评对照。7 题上与本人评分一致率 1.00、MAE 0.0371；但样本小，只能说明"无系统性偏差"，不能说"准确"。 |
| 分数能不能跨模型比？ | 不能。同一份输入换模型，单题最多差 18 个百分点、方向不一致。所以每场都记录本场模型名，只做同场比较。 |
| 参考要点是谁定的？ | 我自己按岗位方向建的题库，100 题、每题 2 个维度、要点写在题里；覆盖面依赖作者经验，这是已知局限。 |
| 命中/缺失是人工标注的吗？ | 不是。是模型按参考要点逐条判定 + 规则口径做交叉，口径都写进产物；真正的"金标准"要人工标注，这是下一步。 |
| 如果回答答非所问呢？ | 提示词里明确要求"明显答非所问直接给弱判定并说明"；同时长度惩罚会标记"回答过短"，避免关键词堆砌拿高分。 |
| 这套评分能用在别人身上吗？ | 可以直接用（题库和评分协议与个人无关）；但要重新做人评校准——评分标准尽量通用，人的表达习惯会变。 |

---

## 5. 诚实边界（主动说出来，比被问出来强）

1. **它不是人工标准。** 现在的一致性是"和本人评分对齐"，样本 7 题、同场同源；要 ≥15 题才有统计意义。
2. **跨模型不可比。** 换模型后分数会变（单题 ±18 个百分点），所以每场必须记录模型名，只做同场比较。
3. **要点口径仍是关键词级的。** 参考要点是词/短语，语义等价但用词完全不同的回答要靠模型分兜；
   更彻底的做法是让模型输出"语义等价的证据句"再人工抽检。

---

## 6. 如果让我继续做（三条改进，答完加一句显得有规划）

1. **固定评分模型 + 人在同一模型下校准**：模型名进产物（已做），样本扩到 ≥15 题后给出稳定的一致率与 MAE。
2. **把要点判定从"关键词"升级成"证据句"**：让模型输出回答里的原句作为证据，人工抽检 20% 抽查准确率。
3. **双评分 + 分歧检测**：同一回答用两个不同模型/两个不同提示词各评一次，分歧大的题自动标"需人工裁决"。

## 7. 60 秒口播稿（可直接背）

"我的评分是两层的。出题时每道题就带着评分维度和参考要点，比如一道 GIL 的题，
覆盖度维度要看 CPU 密集、IO 密集、多进程、异步这几个点，深度维度看有没有实测数据。
打分时先让模型读题、读要点、读回答，输出结构化评分：每个维度 0 到 1 分，命中和漏掉的要点都只能从参考要点里挑，
不允许自己造词；总分是按维度权重加权归一化，0.7 以上算扎实，0.4 到 0.7 算一般，低于 0.4 且缺口两个以上才追问。
同时保留了一条确定性的规则打分做兜底，因为模型会抖，而且评测要能复现。
我实测过一个关键差异：同一段内容，如果说法和参考要点用词一致，规则分给 1.00；换成自己的话讲同样的内容，
规则分直接掉到 0.00，而模型分是 0.88 到 0.95——所以我用模型主判、规则兜底，并且把用的是哪个口径写进产物。
最后我做了两层验证：换一套协议的机器复核，以及本人人评对照，7 道题上一致率 1.00、平均绝对误差 0.037。
样本还小，所以我只说'没有系统性偏差'，不说'评分准确'。"
