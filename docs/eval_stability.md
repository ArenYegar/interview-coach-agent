# 评测稳定性：同一份输入重复打分，分数能差多少

## 问题

同一模型、同一份 JD/简历、同一批预设回答，**连跑两场**（`cost-demo-7` 与 `guard-on-7`，选题逐字相同）：

单题最多差 30pp（技术-03 从 0.50 → 0.80），overall 0.515 → 0.554。
这一条直接决定了三件事能不能做：效果有没有提升、A/B 谁更好、简历上那个数字敢不敢报。

## 先分清差从哪来，再动手

至少有两个可能来源，混在一起就无法判断该怎么修：

1. **采样随机性**（temperature + 每次调用都是独立采样）；
2. **prompt 本身变了**（例如加入注入防护的定界符）。

探针 `coach/eval/stability_probe.py` 对**同一题、同一答案**按条件分组重复打分，
判定用的答案直接取自 `data/answers_by_category.json` —— 与出问题的那两场同一份输入，可复现现场。

## 实测结果（deepseek-flash，2026-10-08）

题目：技术-03、技术-01；每档每题材 3 次。

| 条件 | 平均极差 | 最大极差 |
| --- | --- | --- |
| A 原始口径 temp=0.3 / guard=0 | 5.5pp | 11.0pp |
| B 加防护 prompt temp=0.3 / guard=2 | 7.5pp | 10.0pp |
| C temp=0 / guard=2 | 6.0pp | 10.0pp |
| D temp=0 / guard=2 + seed=42 | 15.0pp | 25.0pp |
| **E 中位数×3（guard=2 / reps=3）** | **2.5pp** | **5.0pp** |

## 四个结论

1. **`temperature=0` 消不掉抖动**：C 仍有 6.0pp 平均 / 10.0pp 最大极差。
   说明差值主要来自采样层面的噪声（服务端批处理、MoE 路由、浮点非确定性都可能贡献），
   **不是温度这个旋钮调出来的** —— 常见做法"把温度设 0 就稳定了"在这个端点上不成立。
2. **加 `seed` 反而更糟**（D 达 25pp）：OpenAI 兼容协议里 seed 是"尽力而为"，
   本端点显然没有真正固定住采样；传它没有收益，因此不启用。
3. **prompt 变更不是主因**：A/C 与 B 同量级，说明"加定界符把分数改了"这个猜测可以排除。
4. **有效的是把「一次测量」换成「多次取中位数」**：E 把平均极差从约 6pp 压到 2.5pp、
   最大从 10pp 压到 5pp。代价是每题成本 ×3（实测 1 题 reps=3：5,848 token / 10.3 s）。

## 落进项目的做法

- `COACH_SCORE_REPS`（默认 1；评测/回归建议 3）：`score_answer` 对同一题打 N 次、取**中位数**，
  并取最接近中位数的那一次样本作为返回（保证 evidence 与分数自洽）；
  `ScoreCard.reps` / `ScoreCard.sample_totals` 记录每次分数，产物里能直接看到这一题的散布。
- `run_demo.py --reps 3`；启动时打印 `[评测参数] temperature / guard / reps`，
  和 `llm_model` 同一套纪律 —— **两次运行的参数不一致，就不该直接比数字**。
- 比较口径：两条策略/版本的差异必须**大于噪声带**（当前单题约 5pp、整场均值约 2-4pp）才下结论。
- `temperature` 与 `seed` 明确不作为稳定性手段（实测无效/有害），写进 `.env.example` 的注释里，
  避免后来的人再走一遍这条路。

## 还剩什么没解决（诚实边界）

- 中位数×3 只是把抖动压小到 5pp 量级，**没有归零**；要更强的稳定性只能增加重复次数（成本线性上升）
  或换成更稳的评分协议（例如把"打分"改成"逐条要点判定"这种离散任务，离散输出的抖动天然更小）。
- 这两道题、3 次重复的噪声带估计仍然很粗；要真正定出"比较判定线"，需要在 ≥10 道题上重复 ≥5 次。

## 面试口径（30 秒）

"我做评测时发现同一份输入连跑两场，单题最多差 30pp。这个数不解决，'提升了几 pp'就全是噪声，
所以我先做了个分组探针把差分的来源分开：结论是 temperature 设 0 消不掉、加 seed 反而更糟、
prompt 变更也不是主因 —— 它是采样噪声。既然调参数没用，我就把'一次测量'换成'每题采 3 次取中位数'，
平均极差从 6pp 降到 2.5pp，代价是成本 ×3，所以只在评测模式开。
最后我把'差异必须大于噪声带才下结论'定为比较口径，并把 runs 的 temperature/guard/reps 都记进产物。"
